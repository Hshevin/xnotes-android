# 工作区文件冷启动与暂停写回（2026-11-22）

用户要求：已自动保存的工作区笔记与画布在冷启动后继续使用原文件，不要求另存；未保存或未绑定的工作副本仍需保护。
状态：已实现；JVM／Robolectric 验证，Android 仪器测试运行及 MovinkPad 真机生命周期待验。
本轮边界：未打包、安装、推送或发布。

从后台返回并不等同于冷启动。进入后台时，应用先请求每个实际拥有者写回已绑定的修改；两个窗格共享一份笔记时只写一次。写入完成后再保存布局。不强制提交未确认的手势。

只有完整、干净、绑定在工作区内且正文版本与已读取或已发布来源一致的文档才获得 v4 `reopenFromFile` 标记。待确认录音不能据此跳过工作副本。正常检查点仍写工作副本；无需直开的布局保持 v1／v2／v3 格式。

恢复先按 UUID 在工作区解析位置，否则用仍在工作区内的原路径。读取的是磁盘上的当前版本，而不是上次的缓存。采用前再次核对类型、UUID、位置和 SHA-256；原件丢失、身份改变、不可完整解码或存在冲突的原生恢复记录时不接管原件。共享阅读窗格重新连接同一个文档，并保留自己的视图。

**崩溃窗口：**缓存和布局不是同一次文件替换。在改写需要保护的工作副本之前，缓存发布流程先建立 `prefer-working-copy` 标记。即便只写完正文、还没写元数据或新布局就被终止，旧的直开标记也不能跳过工作副本。只有已证明可从磁盘重开的捕获完整写入缓存后才移除该标记。它只能阻止直开，不能授予原件写权限。
