# 活模型复制身份与会话依赖规格（2026-11-08）

用户要求：按新渲染架构继续实现思维导图和文件关系网络；页面复制、另存与导出副本获得新页编号，原引用仍指向原页；保留已有内容、撤销和视口。
状态：模型 API 已实现；289 套件 / 3106 项 JVM 测试通过，Android 仪器源码编译成功；独立代码复核完成。实际 Android / 目标设备未运行。
本轮边界：源码、测试、文档、本地提交；不打包、安装、推送、合并或发布。

## 已核实的入口

- `Editor.save` / `saveToThen`、`forkNote`、`writeMergedNote` 改文档 UUID，但当前活页仍携带旧页 UUID。原始包复制/导出已在 R1b1 修正，不能替代这些活模型入口。
- `Document.snapshot` 克隆 Page、冻结页 ID 与层成员，仍共享按现有发布规则更新的内容对象；不能重写其所引用的原模型身份。
- `Page.deepCopy` 不保留页 ID。`Document.deepCopy` 当前保留文档身份、刷新成员身份，不能未经调用方区分就把它改为“另存”的通用入口。
- `ForkLedger` 只转发 URI；旧排队快照还需要使用同一复制上下文转成最新目标身份，不能每次再生成一组页 ID。
- `SessionStore` / `CanvasSessionStore` 仍是独立正文与 sidecar、无请求代次；旧后台快照可能晚到，metadata-only 更新也可能把旧正文配到新身份/位置。复制身份接入前必须补会话绑定。画布会话目前同步写活模型，同样需要主线程快照及后台持久化。

## R2b2a：先实现可验证的页复制上下文

本片先实现模型层 API，不把未就绪的 Save-As/会话流程半接入。原 `ReferenceIdentity` 继续一次赋值；新文档 scope 的身份转换创建新容器，不修改旧容器中的值。只为 Page 增加内部 scope 标记，不添加对象编号，不改变 Page.uid / GlueIds。

建立不可变 `PageReferenceScope`：本 scope 文档 UUID、父 scope 及版本化的身份派生规则。新复制的文档 UUID 必须不同于当前与祖先。用新文档 UUID 的 namespace 和明确的原 scope/页 UUID 确定性生成新页 UUID（UUID v5）；不是按页码、位置或内容相似度猜测。链式复制可将 A 的旧快照通过 A→B→C 转为 C；同一旧页重复计算始终取得同一新 ID，计算顺序和页面重排不影响结果。

复制操作有两个明确步骤：

1. 在模型拥有者准备引用后，创建复制上下文；把已冻结的 snapshot 投影为新文档 snapshot。投影创建 Page 外壳和新引用容器，保留现有内容采样、布局、PDF 指纹、图层快照；原模型与原快照不变。旧排队 snapshot 可投影到同一上下文；已经在目标 scope 的快照不再次换 ID。
2. 目标文件发布成功后，拥有者才采用该上下文。保持实际 Page 对象及 uid、内容、历史和视口；预先验证全部身份后一次采用。捕获期间存在、但发布前被删除的页也能在撤销恢复后取得同一新身份；早先已删除的旧页在恢复后准备 snapshot/引用时按明确 scope 转换。新增页取得当前文档的新身份，页面深拷贝不继承旧身份。

为避免破坏尚未改造的旧调用，不在此片给所有 UUID setter 隐式添加换页 ID，也不提前让 writer 根据身份变化自作决定。复制上下文只通过显式新 API 启用；生产 Save-As/fork/merge 和会话会在接续阶段一起接入。普通 writer 不分配或补活模型 ID。

### 验收

- 原/副本文档和页身份分离，PDF 指纹、笔画压力/时间与图层冻结语义不变。
- 重排、重复投影、链式复制和不同线程投影得到同一对应关系；快照不依赖后来的活模型字段。
- 采用不换 Page 对象/uid，不增加内容历史；删除页撤销、发布期间新增/删除页、页面深拷贝均有行为回归。
- 非拥有者、错误 scope、重复成员/ID、候选身份碰撞/无效身份时不部分修改原模型。
- legacy 未启用引用时不借复制激活页编号。旧 identity 容器仍可读旧值且不能被改写。
- 本片不宣称旧 Save-As/fork/merge 已修好，不开放页来源界面。

## 接续阶段

R2b2b 补会话正文/metadata 的完整绑定、请求代次与来源 scope。必须保留上次完整版本，拒绝旧请求覆盖新状态；view-only 更新不得把旧正文绑定到另一文档，也不应为每次视图变化复制整份 PDF。主线程冻结画布会话，IO 只读快照；原生保存尚在途时不能把缓存误记为“已全部保存”。旧缓存、损坏记录与恢复状态必须明确，不静默删唯一数据。

R2b2c 再接输出流打开前的创建/另存上下文，以及已验证发布后的 live adopt、排队快照和 ForkLedger。新建证据来自明确的创建流程，不能只凭空文件；模型切换后迟到结果不写错文档；新来源 UUID / 页 UUID 和原引用保持分离。缓存保存/恢复必须携带该转换信息，不能把旧页 ID 再写回新副本。

之后继续原字节页锚点激活与实时/会话身份对账、页面多来源、来源往返、反向引用和文件网络。尚待用户答复的“部分保存后放弃”只影响后续清理/回退，不阻塞本片纯身份计算。所有既定产品需求保留。

## R2b2a 实现与验证

`PageReferenceCopy.prepare/project/adopt` 已加入，拥有者 token 与精确父 scope 均需匹配。Page 通过单个 volatile binding 发布身份容器与 scope；旧容器保持旧值，live Page/uid/历史不替换。模型 owner 先计算全部转换并查重/碰撞，再采用；被撤销恢复的祖先页面在下一次 owner prepare 中按确定的父链转换。codec 完整读取成功后只绑定已验证页面，不新增 ID。scope 为运行时身份依据，不写入 xnote，不引入对象编号；未启用引用的 legacy 复制不新增页编号。

投影只接受该拥有者的 writer snapshot，复用现有冻结图层成员与内容采样，不由 IO 线程补活模型 ID。重复投影、链式 A→B→C 和旧排队快照有一致结果；已采用副本的 UUID 被旧 setter 改写时准备/写出拒绝。旧生产另存路径还未接此 API，明确不据此宣称该路径修好。运行时祖先链上限 1024，超限与目标 UUID 回到祖先均拒绝，避免循环和无界恢复描述。

身份派生为独立实现的 UUID v5，按 [RFC 9562 §5.5](https://www.rfc-editor.org/rfc/rfc9562.html#section-5.5) 的字节序与位域规则，使用 Appendix A.4 标准向量验证；未复制第三方代码。
