# 文档登记表版本与回装边界（2026-11-10）

用户要求：说明登记表 v2 对旧构建的影响，制定不会丢失可恢复信息的后续升降级策略。
状态：兼容边界已核实；保留信息的拒绝降级行为补充 JVM 与 Android 平台用例，平台执行待验证。
本轮边界：源码、测试和文档、本地提交；不打包、不安装、不推送、不发布。

登记表 v2 增加页面永久引用契约。合并前只认识 v1 的旧构建不能读取 v2，也不能靠本次修改使已经发布的旧二进制获得兼容能力。同一安装身份回装旧构建需要先清除应用数据；进行试验应优先使用独立分支测试包名。

清除数据会删除私有恢复资料、授权和共享 PDF 原件。需要回装时，先从应用导出完整可编辑备份并处理未保存的恢复资料，不能只复制引用式 `.xnote` 内部文件。不同包名的私有数据互不共享。

## 后续版本策略

- 已知升级只增补结构并保留原行：当前 v1→v2 只增加页面契约表。
- 未知升级或降级拒绝打开，保留数据库与原始版本；不删除数据库，不用“重建索引”清除页面契约、迁移恢复记录、资源引用或租约。当前继承 SQLiteOpenHelper 的拒绝降级行为符合此策略。
- 新增版本如需兼容降级，应在发布前设计可往返的结构，验证旧读者能够保留未知信息；不具备证明时继续拒绝降级。提供恢复工具时，保留原数据库及其一致性快照，再显式转换副本，绝不在打开失败时自动清库。
- 登记表不是笔记的替代备份；恢复必须结合原文档身份、原 PDF 摘要与持久保留的迁移资料，不能从同名文件猜测来源。

回归用例将实际数据库标记为未来版本，再用当前 helper 打开，核实拒绝之后版本、页面契约、来源位置和迁移记录仍完整。此项是对安全行为的保护测试，不人为构造一个会清除资料的“修复前失败”。
