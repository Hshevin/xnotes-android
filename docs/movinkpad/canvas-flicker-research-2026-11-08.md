# 无限画布侧栏黑块与图层闪烁：成因与渲染方案调研（2026-11-08）

用户要求：无限画布体验差，开关侧栏时屏幕有黑块闪烁，开关图层时笔迹闪烁；提出借鉴 Krita 的画布渲染方案，并调研其他带无限画布的开源项目。

## 当前渲染结构

- 主画布 `InfiniteCanvasView` 是 GLSurfaceView（MSAA，按需渲染）；每帧用已上传的三角网格重画全部可见内容，缩放与平移只改 uniform，不存在按分辨率栅格化的缓存。
- 湿墨 `GlWetPad` 是另一个 SurfaceView，API 31+ 在其下挂独立 SurfaceControl 子层做前缓冲。
- 两者与工具标记 View 同在 `surfaces` FrameLayout 中。

## 成因（推断，待复现确认）

### 侧栏黑块

`MainActivity` 画布窗格用 `Row { 侧栏; Box(weight(1f)) { AndroidView(surfaces) } }`。开关侧栏会改变两个 SurfaceView 的宽度与左边位置：

- 主画布：窗口中的 Surface 洞口先按新几何显示，新尺寸缓冲要等 GL 线程画完才到；新露出的区域显示窗口背后的黑色。
- 湿墨层：`GlWetPad.resize` 销毁 EGL、关闭并重建子 SurfaceControl，再重新进入单缓冲。
- 画布内容同时随原点平移侧栏宽度，形成整体跳动。

### 图层开关闪烁

`InfiniteEditor.changeLayers` 对显隐、选层外的所有图层操作都调用 `rebuildScene()`：`Edit.Reset` 清空几何缓冲与记录，主线程重新细分全文档，光晕层因 revision 变化重建，SVG 图片先回到占位框再在后台重新生成网格。批次本身原子发布，但光晕与 SVG 的异步重建、以及大文档的整体重做，足以在屏幕上表现为闪烁和卡顿。

## 调研要点

| 项目 | 许可证 | 可借鉴之处 |
| --- | --- | --- |
| Krita | GPL-2+，只借鉴思路 | 每层独立瓦片数据；脏矩形在后台合并到投影，界面始终显示上一份完整结果；`KisCanvasUpdatesCompressor` 合并被包含的更新、保持顺序；纹理瓦片与画布坐标绑定，平移、缩放、改窗口尺寸不失效 |
| Rnote | GPL-3，只借鉴思路 | 笔画为矢量并各自缓存图像，后台按新比例重绘，新图到之前保留旧图 |
| libmypaint | ISC，可复用 | 64×64 瓦片的无界表面 |
| Excalidraw | MIT | 每元素位图缓存；静态画布与交互画布分离 |
| Lorien | MIT | 运行时按点重绘笔画 |
| androidx.graphics / androidx.ink | Apache-2.0，可复用 | `GLFrontBufferedRenderer` 在同一事务中隐藏前缓冲层；`InProgressStrokesView` 只在正式层画好后才移除湿墨 |

Android 侧：SurfaceView 改尺寸的黑边是平台常见问题；最稳妥的是不改尺寸，面板作为普通 View 盖在画布上，只调整逻辑视口。必须改尺寸时，需让 `surfaceRedrawNeededAsync` 等到新尺寸的完整帧。

## 方案建议

不整体移植 Krita 的光栅瓦片引擎：当前矢量网格每帧重画，缩放时始终清晰、不需要重建缓存，这是 Krita 式像素瓦片不具备的。两个症状来自“改 Surface 尺寸”和“小改动走全量重建”，应先针对它们修复，再借鉴 Krita 的原则。

1. **侧栏不改画布尺寸**：侧栏改为覆盖在画布上，画布与湿墨层保持整窗格大小；视口按侧栏宽度设左侧内边距（同现有 `insetRight` / `insetBottom` 用法），画布内容不再跳动。
2. **图层操作增量更新**：显隐只移除或补回该层的记录，排序只发布新顺序，不 `Reset`；SVG 网格按图片缓存复用，不回到占位框；光晕层只在真正受影响时重建。
3. **借鉴 Krita 的原则**：内容生成与合成分离；更新先在后台完成再整体切换，界面始终显示上一份完整结果；更新合并保持顺序。
4. **视性能需要再做**：每层离屏纹理缓存（按画布坐标分块、LRU），让显隐成为纯合成参数。只有在大文档或多图层真机性能不足时才引入，因为它会带来显存预算和缩放重建问题。
