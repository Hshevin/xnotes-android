# 引用改为页面级（2026-11-07）

用户要求：原设计给每页及页上每个对象（每一笔笔画、图片、文字等）分配永久引用编号，数量过多；用户决定思维导图的引用改为「引用页面及页面上的笔记」，即以页面为单位。经讨论确认以下规则，并要求记录进分支文档，供后续 Codex 恢复导图开发时先行调整。
状态：讨论中 → 已决定；源码尚未修改（对象编号仍在 `0f0a8d91` 等提交中），待恢复开发时作为第一步实施。
本轮边界：只更新文档与交接入口并本地提交；不改源码，不打包、安装、推送、合并或发布。

## 决定

思维导图节点的来源（引用目标）以**页面**为最小单位：分页笔记与 PDF 引用某一页及其上的全部内容；无限画布引用整份文档。笔记文件中只为页面保存永久引用编号，不再为对象分配编号。

| 规则 | 内容 |
| --- | --- |
| 引用单位 | 分页笔记 / PDF：页面编号（页面 UUID）；画布：文档 UUID（`BundleIdentity.documentId`），不在画布内建立编号 |
| 区域提示（可选，第一版可不做） | 引用可附带页面坐标中的矩形，**只保存在 `.xmap` 的来源条目中，不写入笔记文件**；内容移动后可能偏离，仅作定位提示，不影响引用本身 |
| 页面删除 | 引用显示「页面已删除」，不自动改指其他页面 |
| 页面复制（复制页面、另存、导出副本） | 副本获得新的页面编号；原引用仍指向原页，与「复制不加入旧引用」一致 |
| 页面移动、重排、插入 | 编号随页面不变，引用不受影响 |
| PDF | 按页引用；原 PDF 不变，页面对应稳定 |
| 画布 | 已定位为画画与草稿（见 `master` 的 `canvas-sketch-only-2026-11-07.md`），引用整份即可；如以后需要，可另行设计引用已保存的视点 |

## 理由

- 数量：每页一个编号，常见文档为几百到几千个，不再触及 `ReferenceAnchors.MAX_TARGETS = 200_000`。原设计逐笔编号，大本手写笔记可能超限，超限后保存失败；文件体积约增 5–10%，内存约 100 字节／对象（估算，未实测）。
- 用法：回看时需要的是「这一页讲了什么」；OneNote 的链接同样以页面／段落为单位。
- 复杂度：擦除碎片、跨页移动、换层、撤销重做等路径无须维护对象编号，B2c 整阶段可取消。
- 容错：审查第 2 项（锚定文档中一张坏图即整份拒绝打开）随对象编号撤除而失效；只需页面编号完整。
- 兼容：`codex/mind-map` 从未打包或安装（见 `authorization-history.md`），设备上不存在带对象编号的文件，改格式没有兼容负担。

## 对现有实现的影响（恢复开发时先做）

1. **保留**：页面 `ReferenceIdentity`、文档 UUID、原字节保真升级候选（B2a，仅需改为只为页面补编号）、复制时铸造新身份的规则、`readInkCopy` 部分抢救（`mind-map-review-fixes-2026-11-07.md` 第 1 项）。
2. **撤除**：对象（`Stroke`、`ImageItem`、`AudioItem`、`TextItem`、`ShapeItem`、`ConnectorItem`、`TapeItem`）的 `referenceIdentity`、`referenceIdForWrite`，以及 `.xnote` items 与 `.xcanvas` 中的 `reference_id` 读写；`AnchorReadState` 只对账页面；`ReferenceAnchors.validateForWrite` 只校验页面；画布不再需要锚点标记。撤除时同步删改对应测试（`ReferenceCodecTest`、模型复制／快照测试等），保留页面相关断言。
3. **取消**：B2c（对象后继：移动／碎片／删除／撤销）。
4. **调整**：C1「文档选区入口」改为页面选择（缩略图列表），可选区域提示存于 `.xmap`；C2 往返定位改为打开文档并跳到该页（有区域提示时滚动到该处）。
5. **审查第 2 项**：随第 2 步作废，无须另做取舍；撤除前现有严格检查仍在。
