## 普通保存

分页笔记和无限画布的现有文件保存统一进入 NotebookStorage 的候选发布事务。私有候选完整生成后，检查原件、候选、实际当前版本的 ZIP 条目、文档类型/version、UUID、页标记、页编号和 PDF 包装/指纹；普通保存不能充当换文档类型、复制身份、首次页编号激活或 PDF 底稿替换。无标记却出现页编号时要求显式恢复。legacy 文件不套用锚点的 token 容量限制。

恢复记录 v3 将 SAVE_NOTE / SAVE_CANVAS 与原件、候选的 SHA-256 写入同一原子记录。发布/恢复/保留当前的验证回调从各自实际读取并验证的记录接收用途，不能另读一次用途推断。正常发布只接受该记录声明的操作；候选已经写入但登记未完成时，ensure 重开/恢复入口只重新核验、登记，不重复覆盖。直接保存遇到已有 pending 仍拒绝新写入，不能未经模型/候选版本协调就把新快照盖上；当前模型保留与重试界面的接续仍需后续完成。

所有目标先保留 durable 原件、候选和 pending。受管文件使用同目录暂存、fsync、摘要核验，在原子 move 前再次核对已观察的目标摘要；暂存期间到达的 B 版本不会被 A 覆盖。opaque SAF 继续保留故障恢复日志，不假设其具有本地原子替换能力。实际目标的无 before-image 拼接已撤除，避免拼接损坏原件后，强校验使原有 fallback 无法修复；后续优化只能在私有候选或可靠原件保护之上实现。

文件回读成功后才执行 note PDF pin 和文档登记，最后清除 pending。已验证 anchored 文件成功保存会登记单调页契约；这只记录已有契约，不替 legacy 分配页编号。类型/契约拒绝不会变成另一种写入 fallback。

## 恢复与证据

显式恢复校验原件，也在同一观察摘要下检查当前版本。能识别的另一 UUID、另一类型或另一原 PDF 不会被旧备份覆盖；部分写入/损坏、已确认缺失，以及已有页信息丢失的同文档可走受约束恢复。

“保留当前”重复核对当前摘要，只将与记录中的 stage SHA 匹配的历史包作为可信历史；当前本身精确匹配已记录摘要时可作为版本证据。可解析但被改写的备份不是可信旧 PDF。即使当前等于候选，也不跳过可验证原件的 UUID、marker 和 PDF 连续性检查，不能把不符合普通保存语义的候选洗成成功。

这里的恢复记录版本不是 `.xnote` / `.xmap` 格式版本。旧记录 `1` 仍支持原件恢复，候选摘要明确只有调用期间一致性，不冒称跨重启 stage 证明；旧无身份升级可以回到原字节版本。原生“保留当前”对 v1 或损坏记录若无法建立 SHA 证据会保留恢复资料并拒绝清除，**不宣称旧 keep-current 行为完全兼容**。完整独立副本/显式身份修复界面仍需后续完成；不能为让旧日志消失而猜身份或删证据。

Editor 的分页自动保存、画布自动保存和显式保存均用 finally 恢复失败/取消操作的 owner dirty 状态，解除当前保存状态；活动任务获得失败回调，取消不冒充成功，也不输出英文取消异常。画布关闭先等待在途保存，再检查结果和新修改，失败后保持原画布打开。进入/退出导图编辑、笔迹历史和渲染接口未变。

## 共享 PDF

NotebookStorage 懒加载并拥有唯一 PdfResources，后者使用同一 registry；全局访问只委托该所有者，避免两个收集锁或错用另一个登记库。仪器工作区不再反射已删除的 PdfResources 独立 singleton。

stage 前持久保护原件和候选的资源并集。恢复中可识别的当前 PDF 也受保守保护，即使随后因另一文档身份而拒绝覆盖。只有资源确实不存在/不可用，且已验证备份内嵌同 SHA 的完整 PDF 时，才允许该恢复例外；可用的同 SHA 资源仍先 pin。原件本身依赖丢失的 external PDF 时继续拒绝，不以预览冒充原件。

note pin、登记、清 pending 完成后才解除 migration pin；清理失败保守留 pin，不把已提交保存报成失败。不以“无 pending”单独清理资源：pin 已提交但 stage 尚未完成，以及清 pending 后进程退出，均可能留下需要验证的状态。崩溃遗留 pin 的保守回收仍待后续实现，当前可能占用额外磁盘，但不误删原件。日志按 location_key 选择，兼容当前 raw URI 及登记的已知旧别名；多份已知记录拒绝选择。不猜测无法关联的旧 URI 日志。
