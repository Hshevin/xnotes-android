# 引用式 PDF 原件缺失的重新关联（2026-11-05）

用户要求：已有笔记打开时显示损坏，提示重新导入／附加 PDF，但应用中没有入口。
状态：已实现；JVM 单元测试 2706 项通过、Android 仪器测试编译通过；新增仪器测试未在设备上运行；待真机验证。
本轮边界：只本地提交，不打包 APK、不安装、不推送。

## 原因（推断）

单份 PDF（见 `pdf-single-copy-2026-11-05.md`）迁移后，笔记文件只保留原件的 SHA-256 引用，原件存于**执行迁移的那个安装包**的 `noBackupFilesDir/ai-pdfs/`。以下情况下当前安装包找不到原件，`NotebookStorage.ensure` 抛出 `PDF_RESOURCE_CORRUPT`：

- 同一授权文件夹被另一安装身份（正式版与 `branchtest.*` 测试包）打开并迁移；
- 应用重装或清除数据；
- 文件拷到另一台设备。

原提示要求“重新附加”，但没有对应操作。笔迹与批注仍在笔记文件中，未受影响。用户设备上的具体触发场景尚未确认。

## 修复

- 恢复对话框在引用式原件无法解析时显示「选择原始 PDF 重新关联」。所选文件完整计算 SHA-256，只有与笔记记录的 ID 一致才写入私有原件库（`PdfResources.restore`）并重新打开；不一致时拒绝，不保存、不修改笔记。
- 提示文字改为说明可能原因、笔迹未受影响，以及另一办法：在执行迁移的安装版本中导出便携包。

## 未解决

- 用户已没有原 PDF、且执行迁移的安装包也不在了时，仍无法恢复底稿；不提供用不同 PDF 强行替换的方式（页面与批注对位无法保证）。
- 用户可见文件夹中的引用式笔记依赖应用私有存储，多个安装身份共用文件夹时会再次出现。是否对授权文件夹里的笔记保留内嵌 PDF，需要用户决定。
- 待验证：新增 `missingPrivateOriginalOnlyRelinksIdenticalPdf` 仪器测试的设备运行；MovinkPad 真机上 SAF 选择器重新关联及重新打开。
