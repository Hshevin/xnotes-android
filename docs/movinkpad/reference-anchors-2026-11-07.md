`AnchorManifest` 对原生 `.xnote`／`.xcanvas` 版本 1 清单中的直接页面、页面直接对象与画布直接对象追加 `reference_id` UUID，不处理未知嵌套扩展中的同名 items/pages。已有 UUID（包括合法 JSON 转义写法）字节原样保留，重复／无效／部分缺失拒绝；未知 item kind 及原数值、笔压、时间、空格、文字、扩展字段保留。升级不构造绘图模型，不调用笔迹简化或 PDF 编码。

`BundleAnchors` 先 hash 并复制出独立、校验一致的暂存源，再以该快照作所有扫描、插入与封装。清单先识别格式，再严格扫描结构，记录已消费 UTF-16 字符的插入点；连续的 REPORT UTF-8 decoder/encoder 复制原字符片段，避免跨缓冲 emoji 损坏。只有新字段插入，其余清单原字节保持。准备期间或发布前来源摘要变化均拒绝；本地发布沿用原子替换保护。SAF 发布、失败提示和登记的接入属于 B2b，本阶段不触发实际来源升级。

候选带独立 `xnotes-anchors.json`（format=`xnotes-object-anchors`，version=1，documentId 与 BundleIdentity 一致）。标记存在时缺失 ID 视为损坏；可信 `expectedAnchored` 状态可拦截标记也被剥离的已知文档。合法空画布也记录标记。若外部写入器同时删除标记、全部 ID，而且没有可信登记记录，不能从原字节推断旧身份；不得声称随机新 ID 恢复了旧引用。

候选流式重封装所有 ZIP 条目，保留非清单原始解压负载的 SHA-256、原身份／已有锚点标记及 ZIP 注释。保留 STORED 资产的存储方式，其他条目使用级别 1。只修改中心目录而遗留旧 local manifest 的方案被禁止：DocumentCodec/CanvasCodec 使用 ZipInputStream，仍会先读到旧清单。源与候选均比较 ZipFile 中心目录和 ZipInputStream 顺序读取的唯一条目、顺序与摘要，遇到孤立／重复 local 记录拒绝。

严格 JSON 是 opt-in，旧笔记默认解析保持原容错路径。升级拒绝重复反转义键、非法数字／控制符、尾随内容、未来版本及错误容器。资源边界：清单最多 512MiB；锚点标记与文档身份条目各最多 4096 字节，摘要阶段已同时检查声明和实际解压量；token 最多 1,048,576 字符、嵌套最多 256、锚点最多 200,000。单键最多 1024 字符，单对象最多 4096 键，活动祖先链合计最多 8192 键／262144 字符。超限、取消或校验失败清理本次临时产物，保留原件；发布前冲突保留候选供调用方恢复。容量限制不构成任意大旧笔记都能升级的承诺。
