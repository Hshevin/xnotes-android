# 统一侧栏工具面板（2026-11-11）

用户要求：文件关系网络、恢复资料也做成下沉菜单，与原 PDF 原件库和 AI 统一侧栏工具区。
状态：源码已集成；25 项相关 JVM 回归通过，Android 切换用例已编写，未运行。
本轮边界：独立工作树实施、主代理审查与本地合并；不本地打包 APK、不安装、不推送、不发布。

## 交互验收标准

- 点击文件关系网络、恢复资料、原 PDF、AI，保留首页侧栏，右侧切换对应面板，当前项高亮。
- 返回键回到所属首页；切换面板释放旧面板的展示拥有权，不能留下不可见的阻塞状态。
- 主首页与分屏窗格首页分别归属；关闭窗格不让异步结果作用于另一侧。
- 网络里的显式打开文档、关系画布和原件阅读继续沿用已验证入口；返回恢复原面板及必要浏览状态。
- 恢复资料不因切换面板授予原件覆盖权限，未完成复制、损坏/未知资料按现有契约保留；选择器结果始终绑定原请求。
- 复用主题 tokens 与黑白样式；窄窗格提供重新打开侧栏的入口。Surface 重挂、输入隔离与平台视觉另行验收。

## 集成审查

Claude `5030f0ee` 将网络和恢复资料纳入 Backstage 的 NETWORK/RECOVERY 面板，并引入共用首页归属与释放逻辑；原件库复用同一插槽。恢复文件选择器移到阅读器宿主之上，控制器随 Editor 释放，不再因显示全屏图形而被提前销毁。

主代理补充一次点击的异步切换：旧网络尚未完成关闭时保留目标操作，只有首页确认旧面板退场后才打开目标；用户点击其他侧栏项会取消之前的待切换操作。Android 用例覆盖网络 → 原件库的一次点击，以及网络 → 恢复 → 原件 → AI → 恢复 → 返回。

相关 JVM 验证：RecoveryPreviewRenderHostTest 3、ColdMainPresentationHostTest 8、RecoveryPreviewControllerTest 6、EditorRecoveryPreviewHostTest 6、OriginalPdfLibraryHostTest 2，共 25 项通过，无失败/错误/跳过。Android 用例仅源码编译，最后的原生宿主保留修正后再次完成主程序与 Android 测试源码编译。实际面板截图、窄屏抽屉、阅读器往返、选择器重建、关闭窗格与目标设备 Surface/GPU 待运行，不能据此声称已全部验收。

主代理另外取消了「所属首页消失且关闭失败后自动切全屏网络」：来源停车失败不允许直接卸载原生表面。此时保留原生宿主，在反馈栏提供受同一关闭检查保护的重试入口。正常从笔记页面进入的局部网络没有首页归属，仍沿原有已停车的全屏入口。
