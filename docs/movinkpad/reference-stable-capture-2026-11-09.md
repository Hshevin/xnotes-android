# 来源保存的稳定内容边界（2026-11-09）

用户要求：按完整计划继续实现导图与文件关系网络；来源采用页面级身份，保留已有进度；允许编译、测试和本地提交，不打包 APK。
状态：步骤 1 与 1b 已实现；最终 309 套件 3436 项主机测试及 Android 测试源码编译通过，独立复核完成；步骤 2–4 未完成，目标设备未验证。

## 已核实的问题与实施顺序

分页和画布的部分选择缩放、旋转在 MOVE 中修改活模型，但取消时只结束手势，未恢复所有成员。因此不能把输入状态回到 IDLE 当作已提交内容的证明。固定 writer 快照只保证捕获后的内容不再变化，不能纠正捕获时尚未提交的预览。

1. 先修复取消回滚：分页端点缩放恢复原 GeoHandle，整体变换恢复所有 geometry snapshot 与原选择框；画布无论 renderer lift 或直接改模型，都恢复原成员、跟随连接线、选择框和空间索引。CANCEL、第二指接管和清除选区都须在丢失旧事务之前回滚。取消不新增历史、不修改 dirty、不发内容提交，后续正常操作仍只形成一次撤销。事件测试共用于 Robolectric 与 Android 仪器入口；仪器未实际运行时明确标记。
2. 接实际 owner 的稳定捕获边界：覆盖两类输入、文本／标签编辑、样式预览、连续正文输入和表格预览；自动保存／工作缓存等待，不主动提交或取消用户手势；稳定后重试。关闭和替换须显式结束编辑并等待保存，不得排队后错误捕获新文档。
3. 分页和画布原生写入、两个工作缓存统一在旧写完成后从同一 Main owner 捕获固定 writer 视图。此片沿用旧存储路径，不能半启 NativeWorkingSession 或给未经核实的旧缓存原件写权。
4. 再继续原生／工作会话交接、恢复、新建／副本与页身份激活，接页面多来源、预览、跳转返回、反向引用和文件网络。后续需求不因本片分期而取消。

## 本片验收

- 实际 DOWN → MOVE → CANCEL 验证模型确实曾改变，取消后恢复原几何和选框；端点缩放、整体缩放、旋转分别覆盖。
- 同页与跨页成员不因取消改变页归属；连接线的几何／端点绑定恢复；画布索引不保留预览位置。
- 已有撤销记录保持，取消不产生新操作；再次正常完成可撤销／重做。
- renderer lift 与非 lift 都验证；不以渲染快照或空操作假装事件回滚。
- 第二指接管不留下原变换；清选区前恢复原内容；取消后的迟到 UP 不提交旧操作。保留既有 stylus 书写忽略掌触、手指橡皮已擦内容形成一次撤销的策略。
- JVM／Robolectric 与 Android 源码编译分别记录；不将其作为 Android 15、MovinkPad Pro 14、Pro Pen 3 或 GPU 验收。

独立计划核查已确认上述取消缺口及生产入口。步骤 1 是可单独落地的必要修复；步骤 2–4 仍保持未完成，不能宣称保存稳定边界已全部接通。

## 步骤 1 的结果与验证

两类控制器现在在 CANCEL、第二指接管与清除选择前恢复活动选择手势。画布精确恢复 geometry snapshot，不使用恒等变换重算；成员和跟随连接线的索引都更新，临时 lift 和捕获字段释放。成功提交先构造命令、再进入 IDLE、再回调宿主，防自动切回工具所触发的清选区撤回刚确认的内容。这不是同步保存稳定通知；后续 gate 仍须等完整输入分发和 owner 内容提交结束。

新增 `SelectionCancelContract` 共 16 项，同一真实 MotionEvent 流由 Robolectric SDK 35 和 Android 仪器入口共用。覆盖端点／整体缩放、跨页旋转、lift／非 lift、连接绑定／空间索引、双指接管、清选区、迟到 UP、后续 undo/redo；成功 resize/rotate/MOVE/JOINT 回调同步清选区也有回归。另覆盖原本 dirty=true 及既有 redo 保留。

- `tmp/selection-cancel-red.log`：初版事件反例运行失败，精确复现取消后仍留几何；两处夹具的 StrokeSnapshot 身份比较和按比例缩放索引探针随后按实际数据修正，没有放宽取消断言。
- `tmp/selection-cancel-focus.log`：定向取消与选区回归、Android 测试源码编译成功。
- `tmp/selection-cancel-full.log`：完整 308 套件、3425 项，失败／错误／跳过均为 0；Android 测试源码编译成功；`git diff --check` 通过。
- 两个独立只读复核无剩余必修；建议的 dirty/redo 与成功回调重入例已补入最终全量结果。

未运行实际仪器、任意 SAF 提供商或 MovinkPad Pro 14／Android 15／Pro Pen 3。未修改前缓冲／Surface／GPU 实现；lift 交接的目标设备显示效果仍须实机回归。

复核另确认跨文档 reset 会遗留旧多边形草稿、连击与 dwell 状态；这是下一独立修复。reset 发生在换模型后，须仅丢弃旧临时状态，不能从新模型调用旧事务的恢复／提交。完整生产保存 gate 与来源闭环仍按上述依赖继续。

## 步骤 1b：文档重置丢弃旧临时状态（已实现）

以取消修复 a168d62b 为基线。分页和画布的 reset 可能已经处于新模型，故不得调用 abort、正常 end、提交或恢复旧成员。直接取消旧计时器，清除 polygon/shape/tape/connector、连击、顶点、跟随连接线及捕获对象等运行时引用，并清除宿主仍显示的旧预览。保持新模型、历史、dirty、身份与内容不变；旧事务是否应提交须由替换前的 owner 流程处理，不由 reset 猜测。

独立复核要求一并覆盖真实调用：`newNote` 在换模型后先纯 reset 再清选区，不能先 abort 旧选择；嵌套 InsertSpace 的 discard 只停止自动滚动并丢引用，不 restore／repair 新模型；PDF clear 失效旧 press generation。画布宿主同时丢弃旧 restyle/refill baseline，并无条件取消颜色拖放 generation（即使拖拽 UI 已结束、worker 尚在处理），清除其窗口和成员引用。正式工具与配置不通过旧长按借用状态重放。

验收：真实笔点两角形成未提交多边形→换模型→reset→切工具，不向任一模型补交旧内容；新模型下一笔正常。旧模型一次 tap→换模型/reset→同位置新 tap 不合成双击；新模型正常两次 tap 仍可双击。已有取消事件回归继续保持。两类控制器分别覆盖，平台与设备边界同上。

结果：两类 reset 清掉控制器持有的旧内容引用、预览和连击状态，旧触摸余流须等 fresh DOWN 后才重新进入编辑。画布保留调用方已采用的新 Selection。分页嵌套 PDF 与插空状态失效，newNote 的调用顺序已调整；画布宿主的样式与颜色任务也在替换前退休。没有通过 reset 补写旧文档，也未借新模型恢复旧成员。
