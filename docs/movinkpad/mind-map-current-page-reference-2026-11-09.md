## 为什么需要实际保存基线

页 UUID 只能证明引用哪一页，不能证明屏幕内容与磁盘同一版本。特别是某些文件提供者没有可靠修改时间／大小：若屏幕是 A，外部已改成同 UUID、同页编号的 C，先普通保存再检查来源会覆盖 C。

本片复用存储层已有的 `publishExpected`。`publishNoteObserved` 仅把原有成功发布所返回的实际版本交回拥有者，保留公共 `publishNote` 的 Unit 接口；没有签发另一套编辑权限。编辑器私有观察记录绑定实际模型、正文版本、规范位置、文档身份及页面 scope。B 发布期间有 C1 时，观察仍表示 B 的正文版本；C1 可以以实际 B 为基线继续发布，不能被误记为已保存。

发起页引用后，该模型／位置的后续自动保存、暂停保存、同目标保存与关闭 flush 也保持严格基线，不能在取消对话框后退回弱时间戳检查。未知基线拒写。实际替换／重新打开／独立另存会退休旧保护；仅取消当前请求不解除保护。

取消请求不会取消已经接受的原生写入。B 确实发布后，只在原拥有者、模型、路径、身份、页面 scope 和原观察记录仍对应时记下 B，不能因请求取消丢掉其证明，也不能把 B 配给新模型。最外层来源保存保护结束时，原模型若仍有 C1，恢复原有自动保存；C1 仍以 B 为基线检查原文件，不要求用户再次编辑或离开页面才能落盘。

重新打开使用 clean-only 路径：若期间有新修改，保留当前文档并转到另存副本提示，不借通用打开流程把冲突内容先写回原件。已接受的保存完成后才核实际来源，笔和内容事务未稳定时等待，不自动确认或取消用户手势。

## 共享导图会话和操作边界

`MapDocuments` 按应用私有目录及规范 URI 管理唯一会话，唯一私有 `ViewModelStore` 拥有 `MapSession`；Activity 和页引用流程只拥有租约。最后一个租约释放时等待已接受保存，只有最新正文已写入文件／恢复日志且没有未确认内容才释放。未安全保留的草稿继续留在该会话，重新获取不丢数据。

目标选择票绑定会话签发者、文档代次、文档 UUID、目标语义及节点／父节点寿命。删除后撤销不能复活旧票。普通并发正文修改不必让整次请求作废，而是把来源合并进最新节点。确认按钮和文字回调也绑定当前选择，旧回调不能为重载后的同编号节点重新签票。

`saveAttempt` 返回本次实际保存的版本和 Written／Retained／Conflict／Changed／Failed 结果。整个会话的 `saving=false` 不是某一次保存成功的证据。重试仅继续保存已经加入的来源，不再执行追加操作。源内容发生变化时重新选择来源，不能以未核实旧预览代替来源证明。
