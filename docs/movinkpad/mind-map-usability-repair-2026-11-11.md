## 当前代码检查

- `MindMapScreen` 使用 `cameraReady` 同时控制 AndroidView 透明度与输入，View 引用、DisposableEffect 清理、布局变更和 IME 就绪 Effect 共同影响显示。必须找出实际失效环节，不能直接取消稳定布局门槛。
- 文本新增先提交默认节点，再通过 `editing` 和持有的 `view` 开启文本事务。View 引用缺失会导致新增已落盘但没有编辑框，需与空白故障共同回归。
- `InkPadView.onDraw` 用 `drawColor` 填背景；`MapInkEditor` 的 AndroidView 没有显式 Compose 裁切。截图显示其灰色绘制覆盖了工具栏，需验证实际绘制边界，不能仅看 accessibility 树存在。
- 普通 `Toolbar` 依赖 `Editor`，但 `ToolbarFrame` / `ToolbarIcon` / 图标可复用；节点的 InkMode 目前仅 PEN/ERASER/LASSO。复用真实共有组件与状态接口，不能创建虚假笔记 Editor，也不顺带扩张笔迹格式与笔型功能。
- `saveMixedArrangement` 在 capture、prepare、publish 或异常时统一报告失败。需定位具体失败分支，检查实际 Map 与 NOTE 的成功保存回执、来源末读及 host 有效性；不可放宽原件覆盖保护来让保存通过。
- 现有 Android 宿主测试可复用，但部分测试直接调用 View 回调/会话；新增真实 Main 就绪、实际屏幕像素及用户按钮进入编辑的回归，不以 View 存在替代可用。
