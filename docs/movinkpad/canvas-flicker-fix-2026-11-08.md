# 无限画布侧栏黑块与图层闪烁修复（2026-11-08）

用户要求：实施 [调研记录](canvas-flicker-research-2026-11-08.md) 中的方案 1–4（侧栏不改画布尺寸、图层增量更新、借鉴 Krita 的“先备好再整体切换”、显隐成为纯合成参数）；不构建 APK。
状态：已实现；2849 项 JVM 测试通过、仪器测试编译通过；未在模拟器或真机上运行，修复效果待真机验证。
本轮边界：源码与文档本地提交；不打包、安装、推送或发布。

## 改动

1. **侧栏覆盖画布**（`MainActivity` 画布窗格）：画布与湿墨两个 SurfaceView 始终占满窗格，开关侧栏不再改变它们的尺寸和位置；侧栏作为上层面板盖在左侧，并接住所有指针，不把空白处的触摸漏给画布；浮动工具栏让到侧栏右侧。`InfiniteEditor.setSidebarCover` 把侧栏宽度并入视口左内边距，供居中与适配使用；与工具栏遮挡不同，它不重新居中，所以开关侧栏时笔迹原地不动。
2. **图层操作增量更新**（`InfiniteEditor.syncScene`）：图层编辑、图层历史的撤销重做、叠放顺序调整（`replaceAll` → `onReset`）不再 `Reset` 整个场景；按编辑器记录的条目与所属层求差：移除的删记录，新增的细分，换层的只改记录上的层，再在同一批次发布显隐与顺序。已上传的几何不重新细分或上传，SVG 保留已有网格，不回到占位框。只有打开文档仍整体重建。
3. **先备好再整体切换**：差异更新、隐藏层集合与全层顺序都在一个 `scene.batch` 内原子发布，GL 线程一帧内要么看到旧状态、要么看到完整的新状态（沿用场景批次机制）。
4. **显隐是绘制参数**（`CanvasScene`）：记录在生产者线程快照所属层；隐藏层的记录与几何留在 GPU 上，剔除、小地图、拖动层与光晕都跳过隐藏层。重新显示只换一个集合，下一帧即完整呈现。顺序改用 `DrawingLayers.stacked`（含隐藏层），隐藏层的 z 值保持正确。不属于文档的临时笔画（无 layerId）永不隐藏。

未采用按缩放级别的每层离屏纹理：渲染器每帧画的是已驻留的矢量网格，开销主要在 CPU 细分；纹理缓存会在每次缩放平移时失效，并带来显存预算问题。改为保留隐藏层网格，可以达到 Krita 分层缓存的同一目的（显隐不重建内容）。

## 风险与待确认

- 隐藏层的网格常驻 GPU，图层很多且大量隐藏时显存占用高于以前。
- `onReset` 改为增量的前提是 `replaceAll` 的调用方不改条目几何（当前只有叠放调整与图层历史）；以后新增调用方若改几何，需走 `onItemChanged` 或显式重建。
- 侧栏在左侧盖住部分画布；在侧栏下方区域无法书写，需关闭侧栏或平移画布。
