# 保存后放弃修改的含义（2026-11-08）

用户要求：回答保存已写入文件、但后续步骤报错时的放弃语义；选择“保留已写入版本，只放弃之后的新修改”。
状态：产品决定已确认；原生producer/pending/另存统一接线尚待实现与验证。
本轮边界：记录用户决定并继续代码、测试、本地提交；不打包、安装、推送、合并或发布。

## 已确认的决定

文件已写入的版本保留。后续选择“放弃修改”只放弃之后的新编辑，不把来源文件回滚为此次保存之前的版本。该决定解除此前保存/恢复工作中等待此问题的产品语义阻塞。

## 接线必须遵守的边界

以下是实现这一决定的数据安全约束，不是新增的用户选择：

- “放弃”不得触发旧原件/旧缓存写回，不能恢复A来覆盖已经写入的B，也不能覆盖后来外部修改的C。
- 目标中已完整写入的候选需经实际字节摘要、kind/UUID/页面与原PDF契约核实，才可作为“已写入版本”采用；后续登记/pin/日志步骤失败不把它倒回原件。相关pending要与目标现状核对，不靠FileStamp/同名或dirty猜测。
- 未核实的部分写入/损坏目标不能冒充完整版本；保留候选、原件备份与恢复资料，提供显式完成保存/另存等恢复路径，不借“放弃”静默把坏目标当成功或恢复旧内容覆盖现状。
- 选择放弃后的新工作区/来源上下文须来自真实读取与核实；缓存和未采用草稿仅在其实际影响与选择一致、资料已有可靠去处后清理。清理失败不能掩盖仍存在的恢复资料。
- 原PDF SHA-256、资源引用/租约与页面永久身份规则仍有效。用户选择不授权替换不同PDF、删除源文件或删除共享PDF原件。
