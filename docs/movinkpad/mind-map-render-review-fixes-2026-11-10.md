# 导图视口裁剪与绘制缓存实测（2026-11-10）

用户要求：B6 先测后改，只做视口裁剪、文档可见集合、路径、笔迹配置与文字缓存的低风险优化，不改湿墨或前缓冲。
状态：JVM 软件 Android Canvas 基准及六个行为回归通过；八组场景的内容摘要与像素摘要前后一致。目标设备 GPU、帧时间及实际笔延迟未运行。
本轮边界：源码、测试、文档与本地提交；不打包、不安装、不推送、不发布。

## 测量方法

JDK 21、Robolectric API 35 原生图形模式的位图 Canvas，960×640；1000 节点、1200 笔（每笔 64 个采样）、999 层级线、200 条普通关系。每场景预热 5 帧，采样 30 帧，表中单位为毫秒。实际 MapPainter 和 MindMapView 均参与；仅计绘制段，像素校验在计时之外。本机样本不是 Android GPU 或 Pro Pen 3 测量。

## 改动与边界

- 使用当前 Canvas 的变换和裁剪保守跳过屏外节点、层级曲线、关系箭翼与说明；端点在屏外但穿过视口的线仍绘制。节点来源文字和折叠数量外伸也计入裁剪范围。
- 可见集合按不可变文档实例及展开集合缓存；变更文档或展开集合不会沿用旧结果。绘制帧缓存几何和隐藏数量，层级曲线共用 Path。
- 稳定笔迹成员仅在文档实例变化时重建，上一帧临时预览及时驱逐；相同颜色不逐笔复制工具配置。文字排版采用 2000 项有界 LRU，冷条目增长不会整库清空。
- 六个回归覆盖可见性失效、热排版缓存、同色配置复用、活预览几何驱逐、屏外穿线/箭翼/说明/折叠标记，以及屏外小节点的长来源文字进入视口。

未修改湿墨层、局部脏区、Surface、GPU 或前缓冲策略；全图绘制仍随可见内容增长，擦除复杂度不在本项处理。没有据此宣称解决书写延迟。
