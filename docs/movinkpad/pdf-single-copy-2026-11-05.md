# PDF 单份存储与便携导出

2026-11-05：用户明确要求日常不在 `.xnote` 中重复保存 PDF，导出再嵌入，重点保障旧笔记与失败恢复。本阶段只修改、验证代码并本地提交，不打包 APK、安装或推送。

## 存储与兼容

- 日常分页笔记仍采用 ZIP 保存批注、图片等内容；`xnotes-identity.json` v2 表示 `pdfResource` 指向应用私有 `noBackupFilesDir/ai-pdfs/<SHA-256>.pdf`。数据库继续只管理身份、位置与资源引用，没有把笔迹迁入 SQLite。
- 原件按内容共享，文档 UUID 与 PDF 内容 ID 分开。新导入、合并、保存分叉及自动保存使用引用式包。显式另存、分享和导出使用包含 `assets/source.pdf` 的便携包及 v1 身份；保存的便携副本再次作为工作笔记打开时会迁移。
- 旧笔记按打开顺序迁移，不启动全盘扫描。尚未打开的旧包、用户保留的外部源 PDF、显式导出副本、迁移恢复资料以及临时显示/编辑文件，不会被当作重复原件自动删除。因此“单份”指迁移成功后的受管原件，不承诺扫描清理设备上的所有 PDF。
- 内部笔记单独复制不能用于跨设备恢复；分享／导出会补齐原件。私有原件随卸载或清除应用数据消失，必须提前导出完整包。旧应用版本不支持引用式内部包，应使用便携导出包。

## 迁移与安全

1. 保留现有文档 UUID；旧包无身份时先沿用已有字节保真身份迁移。
2. 分块接收 PDF、计算 SHA-256，验证共享对象（已存在对象也检查内容），登记并持久引用保护。
3. 在独立候选文件中移除 PDF 条目、更新身份，复制其他条目，不经过模型重编码。比较所有剩余条目的 SHA-256，包括笔迹 JSON、未知扩展字段和附件；检查源文件未被并发修改。
4. 本地文件同卷原子替换；外部 SAF 通过已有持久恢复日志，保留原包及候选，写后回读校验才清理。失败或外部修改不宣称成功，使用现有恢复入口处理。恢复旧包后仍可重新迁移。
5. PDF 笔记日常保存不使用直接破坏原 ZIP 的尾部拼接；先完整编码再原子发布，SAF 使用恢复日志。普通非 PDF 笔记原有尾部优化不在此次改动范围。

共享原件缺失／损坏时拒绝打开引用式笔记，不静默显示成空白底稿。资源 ID 限定为 SHA-256，不接受任意路径。已验证的私有原件按大小和修改时间缓存校验结果，避免每次自动保存都重新读取整本扫描书；新进程或文件状态变化重新校验。

缩略图、PDF 导出和合并清理只删除自己的临时 PDF，不删除受管对象。笔记引用仍采取保守保留策略，永久删除才释放；多笔记共用及 AI 租约继续阻止回收。便携导出期间也持有租约。无引用、无有效租约并超过保留期才允许回收。迁移失败可暂时多占空间，优先保留数据。
