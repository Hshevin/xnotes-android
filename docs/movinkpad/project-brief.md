# 项目说明

状态：已建立 Pen Input Lab；2026-10-30 按用户要求转为基于 XNotes 开发第一版，已实现三键映射与黑白调色板，Release 98 已通过目标真机验收（[记录](device-acceptance-release98-2026-11-08.md)）。完整笔记功能对齐尚未完成，见 [第一版记录](xnotes-first-version.md)。

## 已确认的目标

- 专供 Wacom MovinkPad Pro 14 使用，兼容设备配套 Wacom Pro Pen 3。
- 功能与交互逻辑对齐 OneNote **Android 平板版**，由用户明确选定。
- 不考虑云端同步；笔记内容在设备本地保存。
- 当前先交付笔输入测试软件，采集不同快捷键下的输入，供后续笔记软件开发。
- 2026-10-30 新增：支持导入上千页、数百 MB 的扫描 PDF，在独立标注层直接书写，保持原始 PDF 不变；选中工具时显示随笔尖位置和当前工具变化的光标，参考 CSP / PS。详细规划见 [计划](../../tasks/plan.md) 与 [任务清单](../../tasks/todo.md)，功能尚未实现。
- 工具快捷绑定支持用户选择“按住临时启用，松开恢复原工具”或“按下直接切换，松开仍保持目标工具”；第一版已接入两种绑定模式，完整工具光标仍待后续实现与真机验收。
- 正式笔记软件界面简约，仅用黑白：正常模式纯白底黑色文字／图标，夜间模式纯黑底白色文字／图标；选中态用黑白反转区分。2026-11-03 起允许中性灰阶表现层级，并统一字号、间距与 48 dp 触控区；已实现并通过模拟器截图检查，Release 98 已通过日夜间真机视觉验收，见 [黑白层级与字号间距规范](ui-monochrome-tokens-2026-11-03.md)。

## 设备事实与验证边界

Wacom 官方资料说明该设备为 Android 15 独立平板，配备 14 英寸、2880 × 1800 显示屏，支持 60/120 Hz 刷新率；笔输入支持 8192 级压感与 60 度倾斜。上述为硬件规格，不等同于应用已读取或利用这些能力。

官方产品页的规格列出侧键，同时区分配套笔与另售可定制笔。配套实物是否有可用侧键、系统是否将其映射为标准事件，必须检查真机，不预设“三个按键均可映射”。也不假定 Pro Pen 3 带尾部橡皮或支持笔杆旋转。

2026-10-30 补充：用户已反馈三个按键的实测按钮位，第一键为 `0x00000020`、第二键为 `0x00000040`、第三键为 `0x00000004`，不按键为 `0x00000000`。随后提供的 DTHA140 / Android 15 真机日志已证实这些值及其悬停／接触输入表现；系统构建信息、完整统计与测试边界见 [真机日志分析](pen-input-analysis-2026-10-30.md)。后续以 [按钮位映射记录](pro-pen-3-button-mapping.md) 为适配依据。

Android 提供标准笔输入能力，可作为输入验证的起点；是否需要 Wacom 专用接口、低延迟渲染方案以及附加库，均待验证。系统支持防误触也不免除应用处理取消事件和笔触冲突的责任。

## 对齐范围与核对方法

“对齐 OneNote”是整体产品目标；下表为待逐项核实和实现的工作范围，不是已经验证的 OneNote 功能清单。先记录参考应用版本、操作路径和预期反馈，再确定差异及验收用例。分阶段交付不代表缩减最终对齐目标。

| 范围 | 需要核实并落地的行为 |
| --- | --- |
| 组织与导航 | 笔记本、分区、页面的层级、创建、重命名、排序、移动、删除与返回路径 |
| 页面编辑 | 自由布局、文本与笔迹混排、页面标题、背景、缩放与平移 |
| 手写 | 笔与荧光笔、颜色与粗细、橡皮擦、选择与移动、撤销与重做 |
| 内容 | 文本格式、列表、标签、图片与附件等，以参考版实际能力为准 |
| 查找 | 页面及笔记范围的本地查找；手写识别、OCR 是否属于对齐项另行核实 |
| 交互 | 平板导航布局、工具切换、笔与触摸分工、键盘、横竖屏与焦点行为 |
| 本地数据 | 自动保存、退出恢复、备份与恢复、导入导出及失败提示 |

云端同步及其账号、共享协作流程排除在范围外。OneNote 原生文件格式导入导出尚未提出明确要求，不能把交互对齐解释为已承诺格式兼容。设备没有内置相机，相关参考功能须记录硬件限制与替代方式。

## 当前技术方向

2026-10-30：用户明确要求基于 XNotes，正式原型位于本仓库根目录，采用上游 Kotlin / Compose 与其原生绘制实现。保留 外部诊断工程的 `app/` 诊断工具。以下早期候选说明仅作为历史背景，不再要求新建 `notes/` 模块。

### 早期候选

诊断工具采用 Android 原生 Java/Views，直接采集输入事件并导出 JSON，已建立 Gradle 工程。正式笔记软件仍优先评估 Android 原生方案；Kotlin 是候选语言，其 UI 框架、绘制引擎、数据库与文件格式尚未选定。以诊断工具的真机采集结果为依据决定正式架构。

存储设计应保留可编辑笔迹数据和页面对象，而非只保存页面截图。具体模型、事务策略、保存时机、格式版本和备份协议在实现前定义，并验证进程终止与磁盘写入失败。

## 建议交付顺序与验收

1. **参考与输入验证**：整理参考版对照表；真机记录各输入事件、压力范围、倾斜、悬停、侧键、掌触与取消行为。模拟器只用于通用流程。
2. **首个离线闭环**：创建页面、笔写、擦除、撤销重做、自动保存；重启后内容一致。书写中手掌接触不生成误笔迹，取消的笔触不残留。
3. **组织与混排**：实现笔记本／分区／页面及文本与图片混排，检查对象移动和画布变换后的坐标一致性。
4. **数据保障**：备份恢复、导入导出、格式迁移与异常处理；恢复验证以实际内容一致为准。
5. **完整对齐与优化**：完成剩余对照项，真机测量长页面和持续书写的延迟、帧耗时、内存与保存耗时，再制定量化门槛。
