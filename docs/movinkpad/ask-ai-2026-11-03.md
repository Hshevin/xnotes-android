## 实现范围

- PDF 与普通分页笔记共用 `ScreenshotMenu(Editor)`，无限画布使用 `ScreenshotMenu(InfiniteEditor)`，两处均新增「问 AI」。沿用已有选区渲染，包括选区内显示内容；不读取或上传整个 PDF，不更改原稿。
- 偏好设置和浮窗内均可配置 HTTPS 供应商 URL、模型标识、API Key。地址填写供应商完整基础路径（例如 `https://example.com/v1`），自动追加 `/chat/completions`，也接受完整端点。
- 第一版只支持兼容 Chat Completions 的流式图片模型接口；不是任意供应商原生 API 的通用适配。需供应商支持 data URL 图片、SSE 和 `[DONE]` 终止标记。
- 应用内黑白浮窗支持拖动、收起、展开；边界随所在窗格限制。截图预览、移除、输入、发送、追问、新会话、停止和文字长按选择复制。
- 成功的问答才加入后续上下文。失败或停止时保留问题和待发送截图，部分回答可复制，不进入后续上下文。后续追问携带本会话之前成功发送的截图。
- 会话仅保存在内存；关闭浮窗、离开编辑器或进程结束会丢失聊天。不会改变笔记格式。第一版不包含跨应用悬浮窗、聊天历史存储、Markdown/公式排版、窗口调尺寸或停靠、插入回答到笔记、模型列表拉取、独立连接测试按钮。

## 网络和凭据

用户主动点击发送才访问配置的供应商，不预加载、不上传整份笔记。新增 INTERNET 权限，笔记编辑仍离线可用。API Key 用 Android Keystore 的 AES/GCM 密钥加密，配置写入 noBackupFilesDir，使用 AtomicFile 保存；不进入笔记导出或应用日志。拒绝 HTTP、URL 内嵌账号、查询参数和片段，关闭 HTTP 重定向，避免凭据被转发到另一个地址。响应按纯文本显示，不执行工具或模型返回的指令。

截图上限 6 MiB，请求 12 MiB，会话最多 40 条消息；输出上限 4096 tokens，响应流限制 1 MiB，单行限制 64 KiB。连接超时 15 秒、读取超时 60 秒。无自动重试，失败由用户主动重试。截图沿用现有分享缓存生成机制，聊天持有截图字节，不依赖缓存文件长期存在。

协议与密钥设计参考：[Chat Completions](https://developers.openai.com/api/reference/resources/chat)、[Android Keystore](https://developer.android.com/privacy-and-security/keystore)。未复制外部 AGPL 项目代码，未增加第三方依赖。

## 流式回答 null 修复

用户报告回答前连续出现 null。源码定位：AiProtocol.delta 使用 optString，Android org.json 将 JSONObject.NULL 字符串化为 "null"，连续 content:null 帧会污染回答。未获取该用户实际响应，具体模型帧序列仍是推断。参考 [Android JSON 实现](https://android.googlesource.com/platform/libcore/+/refs/heads/main/json/src/main/java/org/json/JSON.java)。

修复为 opt 读取原值后仅接受 String；缺失、JSON null、数字、布尔、对象、数组不追加，真正的文本 "null" 保留，不使用字符串替换。新增连续推理/结束/usage 帧测试及平台仪器测试。JVM 新增非文本强制转换测试在旧实现失败，修复后通过；JVM JSON 库与 Android null 语义不同，不能把 JVM null 测试视为平台复现。

## 本地历史与独立生成生命周期（后续更新）

此阶段替代前文“临时聊天，关闭清空”的行为。当前源码新增左侧导航 AI（展开侧栏与折叠栏均可进入）；列表按最近更新排序，可搜索标题、提问、回答和来源名称，可继续、重命名、打开原文和删除。标题默认第一条问题的前 40 字。图片内容不做 OCR 搜索。

### 会话与生成

- 应用根部唯一浮窗，编辑器截图入口创建带来源标题/URI的新会话；历史点击恢复同一会话。截图保存在已发送问题中，历史可查看截图。
- 关闭、收起、切换文档或新开会话不会取消生成。请求由仅持有 Application Context 的应用级管理器拥有，完成结果更新原会话，历史可显示生成中、完成、失败、停止和中断。
- 主动停止取消连接并保存部分回答；失败/停止/中断轮次提供“重新提问”将问题和截图填回输入框。后续上下文只包含成功完成的轮次，部分回答仍在历史可见。
- 删除需确认，取消该会话请求并移除记录；晚到更新只允许更新仍存在的记录，不能创建记录。删除后 8 秒内可撤销（最近一次删除），恢复已保存问题、截图和部分回答；不恢复网络请求。撤销缓存在内存，进程结束后不可撤销。（2026-11-04 起已改为移到回收站，不再有 8 秒撤销，见 [AI 会话回收站](ai-trash-2026-11-04.md)。）
- 搜索来源随问题保存；继续对话使用当前配置的模型与供应商，联网开关重新打开浮窗默认关闭。关闭搜索不移除已有搜索上下文。

### 存储与故障恢复

每会话一个版本化 JSON，截图以内嵌 Base64 保存；路径为 noBackupFilesDir/ai-history，不参与笔记导出/系统备份，不包含密钥。问题持久化成功后才发送网络请求；生成期间约每秒追加一个保存快照，结束/停止/失败时再保存。单文件限制 64 MiB。

所有写入和删除经同一队列串行处理，临时文件写入并 fsync 后原子替换；替换失败保留旧记录。损坏或未知版本记录跳过但不删除，界面显示错误；保存错误提供重试。启动时将遗留“生成中”改为“已中断”，保留最近成功写盘的部分内容。突发杀进程可能丢失尚未落盘的最后一小段，不能保证系统后台杀进程时生成继续。

未发送的输入框草稿/待发送附件仅保留进程内，已发送的消息与附件才持久化。聊天删除不操作笔记或 PDF；来源移动、删除或授权失效时历史仍可读，打开原文走已有文件打开流程。历史目前整体载入内存，大规模会话库性能待评估。

## 完整聊天页与 PDF 按需读取（源码阶段）

主菜单 AI 使用完整聊天界面，历史列表支持返回继续聊天；文档内继续使用浮窗，来源窗格关闭/回首页时隐藏浮窗，任务继续生成并保存。PDF 阅读器的截图入口同时提供「附加当前 PDF」，默认不附加；支持文件选择器及剪贴板文件 URI。

参考 dsh-Go 的 session_api.dart 文件上传/会话凭据流程，以及 DeepSeek Harness attachment 包的不可变附件与按需读取设计，独立实现 Android 本地版本，未复制其代码或部署 DSH 引擎：
- PDF 原始字节保存到 noBackupFilesDir/ai-pdfs，SHA-256 标识，同内容复用；临时写入、fsync、原子发布后才供聊天引用。来源 PDF 不改变，原文件移动/删除不影响附件。
- 历史 JSON 保存名称、ID、页数，不保存整份 PDF 页图；旧内嵌文字/页图记录继续兼容。
- 使用现有 Chat Completions 流式接口进行有界 JSON 工具循环（不是供应商原生 tool_calls 协议）。只接受当前会话附件 ID，禁止任意路径；每次读取最多5页文字、搜索最多50页返回最多10条、单页渲染1600长边。最多8轮/4张页图/64000字读取预算，达到上限明确标记。
- 读取结果交给检索词识别和最终回答；不开联网也能读取 PDF。扫描 PDF 可按页图读取，没有额外本地 OCR 引擎。不支持指令/视觉的模型可能失败，不能宣称任何模型均支持。
- 单文件200 MB准入上限，取消原30页限制；预算限制针对实际读取。PDF解析的内存、复杂损坏文件与大型扫描件性能仍待真机验证。
