# 大型 PDF 独立标注与工具光标计划


> 2026-10-30 实施更新：用户要求改为基于 XNotes，原型位于本仓库根目录，不再新建 `notes/` 模块。第一版先实现 T16 所涉三键自定义映射和黑白调色板；软件自动化验证与真机验收分开记录，见 `docs/movinkpad/xnotes-first-version.md`。其余大型 PDF、完整工具光标及性能任务继续保留，尚未验收。

日期：2026-10-30。状态：待用户审阅的规划草案，未实现；本次只修改规划文档。

## 1. 已确认需求与规划假设

已确认：

- 设备：Wacom MovinkPad Pro 14 / Android 15，配套 Pro Pen 3；沿用现有实测按钮位。
- 主要文件：上千页、数百 MB 的扫描书。
- 导入 PDF 后可直接在页面上标注，标注如独立图层，不改变原始 PDF。
- 选中工具后，页面中的笔尖光标像 CSP / PS 一样反映当前工具。
- 本地离线，不引入云同步；其余笔记交互继续以 OneNote Android 平板版为基准。本次两项是用户明确提出的扩展。
- 工具快捷绑定可选择两种触发模式：按住临时启用、松开恢复；或按下直接切换、松开仍保持目标工具。具体侧键用途尚未指定。
- 界面简约，正常模式纯白（#FFFFFF）底、纯黑（#000000）文字／图标；夜间模式纯黑底、纯白文字／图标。不使用彩色界面强调色。

以下是建议默认值，可在审阅时调整，不能作为用户已确认事实：

- 一本 PDF 在笔记中表现为一份“文档型资料页”，内部 PDF 页连续滚动，避免把千页导入成千个笔记侧栏条目。
- 源文件导入为应用管理的只读本地副本；标注另存。默认一个可隐藏、可锁定的用户标注层，结构预留 layerId；首版不提供完整多图层面板。
- 写字模式：笔负责当前工具，双指负责导航；笔落下期间冻结页面变换，避免手掌拖动和缩放改变落点。阅读模式允许单指滚动。
- 光标默认是“小工具／笔尖图标 + 准确中心点”，可叠加笔刷范围轮廓；只在有实际笔位置时显示，不把图标停在上次位置冒充实时位置。
- 第一版具备手写笔、手绘荧光笔、整笔擦除、撤销／重做、标注层显示／锁定与本地恢复。分段擦除、文字框、套索、形状、OCR、完整 PDF 导出分后续任务推进。
- 首轮重点样本为 1000–2000 页、100–800 MB；1 GB / 3000 页是压力测试，非已经承诺的上限或性能。需使用合法的真实扫描样本校准。

## 2. 目前可复用什么

原诊断工作区的 `app/` 是诊断工具，不是笔记软件；目前的 `StrokeBook` 是最多 8000 段的临时轨迹，不能直接充当正式笔迹存储。`ProbeCanvas` 只绘制悬停十字，没有 PDF、页面坐标模型、工具系统或可靠存档。

可复用：原始事件采集的经验、真实输入日志、取消行为测试思路，以及按钮映射。不能复用诊断工具的“内存日志／轨迹上限”作为笔记数据容量限制。

历史方案：保留外部诊断 APK；新建 `notes/` 的建议已被采用本仓库 XNotes `app/` 的决定取代。正式包名尚未确定。优先采用原生 Views 承载文档画布；业务代码 Java 或 Kotlin 可在建模块时决定，不为这两项功能先行引入 WebView 或整仓迁移。初期在单一应用模块内按包组织，避免提前拆分大量 Gradle 模块。

## 3. 用户操作与界面

### 黑白主题与简约布局

| 界面元素 | 正常模式 | 夜间模式 |
| --- | --- | --- |
| 页面外背景、工具栏、侧栏、菜单 | 纯白 #FFFFFF | 纯黑 #000000 |
| 文字、工具图标、细边框 | 纯黑 #000000 | 纯白 #FFFFFF |
| 选中工具 | 黑底白图标 | 白底黑图标 |
| 空白笔记页背景 | 白色 | 黑色 |

用户已明确以上视觉方向。采用单层紧凑工具栏、可折叠导航、线性图标和必要的细边框；不添加渐变、装饰阴影、彩色选中态或多层卡片。未选中项保持透明背景；禁用／保存失败等状态用形状、短文字和明确可操作性区分，不依赖彩色提示。图标保持足够的笔／手指点击范围，不以简约为由缩小命中区域。

正常／夜间可手动选择，偏好本地保存；普通笔记页与 PDF 页、菜单及工具设置共用主题。系统状态栏和导航栏在可控范围内匹配主题。此要求面向正式笔记软件，不表示现有诊断 APK 已改为黑白主题。

界面黑白不等于将 PDF 图像或用户选定的笔迹颜色改成黑白。PDF 默认保留底稿原色；若后续需要扫描页夜间反色，作为独立的显示选项，不修改底稿、标注实际颜色、备份或导出。空白笔记页的默认自动对比笔迹须在黑白背景均可见，主题切换只改变显示，不回写已保存笔迹颜色；明确选定的彩色笔迹仍保留其内容颜色。光标在两种背景及 PDF 图像上均需对比清楚。

### 导入

笔记本／分区 → 添加资料 → PDF → 系统文件选择器 → 复制进度 → 打开阅读。复制可取消；大文件显示已复制大小，不假定提供方一定报告总长度。

页首展示文档标题、页码和保存状态；侧边栏展示按需加载的页缩略图，可跳页。工具栏提供笔、荧光笔、橡皮、导航、撤销／重做、颜色、粗细和“显示标注”。可折叠侧栏，把主要空间留给阅读和书写。

在扫描页上进行的是手绘高亮；没有文本层的页面不能冒充“按文字选择高亮”。OCR 属于后续可选能力，不在首次打开时扫描整书。

### 标注

用户缩放到想写的位置，悬停显示当前工具光标，落笔即写入标注层。底稿、已有标注、当前未完成笔迹及光标分别绘制，PDF 渲染不随每一笔重新启动。

“隐藏标注”还原当前底稿显示；“锁定标注”保留显示但不可编辑。锁定或隐藏时禁止继续写入不可见标注；给出明确的锁定／隐藏状态。橡皮仅作用于当前可编辑用户标注层，不会擦掉 PDF 文字、扫描图像或 PDF 原有批注。

首版不允许替换底稿、删除／重排 PDF 页或跨页延续一条笔迹。跨出页边的笔迹按页面边界裁切，不产生跨页连线；侧栏跳页、开菜单或失焦时结束／取消相应临时交互。

### 返回与恢复

返回后记录当前 PDF 页、页内位置和缩放；重新打开后恢复。每页标注按需读取，未打开的千页笔迹不全部装入内存。

## 4. 不改变原始 PDF 的数据设计

分为三个不同职责：

| 数据 | 保存位置与职责 | 是否可丢弃 |
| --- | --- | --- |
| 源 PDF | 文件选择器选中的外部文件，只读取 | 不由应用修改／删除 |
| 应用内底稿 | 导入时原样复制，字节不可变，以 SHA-256 标识内容版本 | 不能按缓存清理；有标注时不能静默删除 |
| 用户标注 | 本地数据库中的页、层、对象与笔迹数据 | 不能按缓存清理 |
| 显示缓存 | 页面预览、瓦片和缩略图 | 可重建，允许清理 |
| 光标／当前笔迹 | 短期交互状态；当前笔迹具有恢复草稿 | 光标不保存到笔记或导出内容 |

导入流程：读取 URI → 在临时文件中分块复制并同时计算 SHA-256 → 关闭文件 → 解析有效性与页数检查 → 同卷原子重命名 → 发布数据库记录。用 pending / ready 导入状态和启动清理协调文件与数据库，避免进程中断后产生“已导入但底稿不存在”的记录。失败和取消只清理本次未发布临时产物。

不要求取得源 URI 的写权限；应用的 PDF 访问层只以只读模式打开底稿。开发验收时比较源文件及应用内底稿在操作前后的 SHA-256，而非只检查文件名或修改时间。导出只新建独立输出文件，不使用源 URI 作为输出。

几百 MB 文件会占用额外本地空间；导入前尽可能检查可用空间，复制中仍须正确处理空间不足。阅读以完整本地副本为基础，首屏计时从副本就绪后开始，不承诺未复制完成就打开不完整 PDF。

标注建议模型：

- DocumentAsset：资产 ID、SHA-256、字节数、路径、页数、导入状态、格式版本。
- DocumentInstance：它在笔记中的条目 ID、所引用的资产版本。相同底稿可去重，但不同笔记中的标注不自动共享。
- PageGeometry：资产版本、原始页索引、稳定页面 ID、可见页宽高、原始旋转／裁切信息及坐标约定。
- AnnotationLayer：所属文档条目、页面、layerId、可见／锁定状态、顺序。
- AnnotationObject：对象 ID、类型、边界、样式、对象版本；笔迹另外保存点、压力、时间和笔刷参数。保留原始采样与格式版本，不把屏幕位图当笔迹本体。
- ReadingPosition：当前页、页内位置、缩放和查看方向；与标注保存事务分开，避免高频滚动反复修改整页数据。

推荐 SQLite 事务保存对象与每页 revision；笔迹数据可先用数据库 BLOB，后续根据真实负载再评估分块文件。每次落笔不是重打包一份包含整书的 ZIP，更不是重写整个 PDF。

写入状态至少区分“正在保存”“已保存”“保存失败”。只有事务提交成功后标为已保存。落笔过程异步追加少量可恢复草稿，抬笔提交完整对象；已提交笔迹应在强杀后恢复，崩溃时最多损失未提交的最后一段，具体草稿间隔在真机测量后确定。保存失败保留内存草稿并明确提示，不能默默显示成功。

## 5. 坐标与渲染结构

显示层次从下至上：PDF 瓦片 → 已提交标注 → 当前交互笔迹／选择框 → 工具光标。每层都只有可见区域需要绘制，光标移动不能触发 PDF 解码。

统一三套坐标：

1. 原始页面／渲染器可见页坐标，使用稳定的页面单位作为标注坐标。
2. 连续文档布局坐标，包含页面间距和每页布局。
3. 屏幕坐标，包含滚动、缩放、窗口边距和屏幕方向。

将页面到屏幕的矩阵统一为一份权威变换，输入坐标用其逆矩阵回到页面坐标；PDF、标注、命中检测和光标落点共用它。禁止笔迹使用屏幕坐标持久化；禁止各层分别计算一套近似缩放。旋转、CropBox、PDF 原始坐标原点及渲染器已应用的旋转在原型中核实，避免重复旋转或上下倒置。

首版笔迹宽度以页面单位保存，缩放后与底稿一起放大。小工具图标大小保持 dp，实际笔刷／橡皮影响范围随页面缩放显示。混合页尺寸、不同裁切与页面原始 90/180/270 度旋转属于首轮坐标测试。

## 6. 上千页扫描书的加载与性能

### PDF 引擎取舍

首选评估 Android 系统 PdfRenderer + 自定义视口／标注叠加。理由是可以掌控页面变换、输入优先级、瓦片和独立存档；本项目目前没有现成笔记视图，不能把这理解为系统 API 自动提供整个阅读器。

同时用小型对照原型评估 AndroidX PDF 的阅读能力与叠加接口。2026-10-30 查阅的官方发布页列出 1.0.0-beta01，EditablePdfViewerFragment 等编辑 API 仍标记 ExperimentalPdfApi。是否采用以目标机的 API／SDK extension、页面变换回调、独立标注接入和输入控制验证为准，不把已有注释按钮当作满足本项目存档模型的证明。

不要为了“图层”要求调用 PDF 修改／写回接口。高保真 PDF 导出单独评估，不能由 compileSdk 36 推断 Android 15 支持所有新 PDF 编辑 API。

### 加载策略

- 只打开文档结构与需要的页；先可见页，再滚动方向邻页，再当前缩略图。远处页用占位尺寸，页尺寸渐进发现并维持滚动锚点，不在首次打开前扫描全部页。
- 页尺寸使用原 PDF 元数据与缓存，不假设全书同一尺寸。跳到未知尺寸的远页时优先读取目标页，尽快显示该页并稳定当前位置。
- 页面预览先提供可读的低分辨率结果，停止缩放后再补当前视口清晰瓦片。放大不会变成一次分配整页超大位图。
- 第一轮比较 512 与 1024 像素瓦片，结合实际扫描书调优。可见瓦片优先级最高；快速滑动时丢弃已过时的待处理请求。已进入原生渲染、无法中止的任务完成后可丢弃结果，不承诺强制取消所有 native render。
- 系统 PdfRenderer 需要可 seek 的文件描述符；同一 renderer 同时只允许一页打开。以受控的后台队列 open→render→close；不要在一个实例上并发打开多页。
- 不默认建立每页一个 renderer，不随页数增加位图与线程。是否允许第二个 renderer 做预取，需要在内存和实际速度对照后决定。
- 原生 PDF 解析／渲染考虑独立服务进程，并限制权限；异常文档导致服务退出时，主应用保留标注数据和错误页面，允许重试／跳过。前期能力原型可用单后台线程，不能把它直接当完成的恢复架构。

### 缓存与内存

- 缓存键包含文档哈希、页、渲染级别、瓦片范围及相关显示参数；不同资产／版本的结果不会混用。
- 内存 LRU 以真实字节数计费，计算像素缓冲、native/GPU、预览与临时缓冲，不只统计 Java 对象。
- 初始位图预算建议 96–160 MiB，设备内存压力时降低；磁盘显示缓存建议 0.5–1 GiB 上限，可配置、可清理。它们是待测预算，不是已经证明的峰值。
- 512×512 的 ARGB_8888 瓦片约 1 MiB；一个 4000×6000 整页约 91.6 MiB，不能按页数预解码保存。
- PDF 底稿、用户标注永远不走显示缓存淘汰。临时笔迹、当前页命中索引和其他页历史均有独立边界。
- PDF 解码、缩略图、OCR、保存与导出使用后台工作；输入事件和当前笔迹绘制优先。高频悬停不创建位图、数据库事务或 JSON 日志，诊断版的完整日志模式不默认带入正式编辑器。

### 待测性能目标

以下是先验收基线再调整的目标，不能当成当前产品保证：

| 测项 | 初始目标／约束 |
| --- | --- |
| 数据集 | 实际 1000–2000 页、100–800 MB 扫描书，另加 1 GB / 3000 页压力样本 |
| 首次显示 | 本地副本就绪后，普通测试页首个可读预览 P95 ≤ 3 秒；极重页面单独记录，不隐瞒失败 |
| 页内浏览 | 已缓存视口内容的 UI 帧耗时 P95 ≤ 16.7 ms（60 Hz）；120 Hz 作为单独调优目标 |
| 缩放补清 | 手势停止后可见区域补清 P95 ≤ 1 秒，在约定扫描书样本上测量 |
| 书写与光标 | 无随 PDF 瓦片完成而出现的明显断笔／跳点；端到端延迟用真机高速录像测，不能用输入时间戳代替 |
| 内存 | 连续浏览 1000 页后峰值受预算约束，内存不随已访问页数单调增长；无 OOM／ANR |
| 保存 | 已保存笔迹强杀后可恢复；源 PDF 与内部底稿哈希不变 |

冷缓存／暖缓存、缩放等级、页尺寸和设备显示刷新率须分别记录。若原型在目标扫描书上达不到指标，先调整引擎、缓存和任务顺序，再扩大 UI 与工具范围。

## 7. 像 CSP / PS 的工具光标

普通空白笔记页与 PDF 页面共用 ToolState、InputRouter 和 CursorOverlay；底稿不同，但工具图标、热点、侧键临时切换与显示设置保持一致。首轮可先在 PDF 原型接入，后续空白笔记页不得另做一套互相矛盾的光标逻辑。

### 表现

| 当前工具 | 悬停表现 | 落笔时建议 |
| --- | --- | --- |
| 书写笔 | 默认小笔尖图标 + 精确中心点，可叠加名义粗细轮廓 | 主要显示真实笔迹；中心标记可保留／隐藏 |
| 荧光笔 | 扁平笔尖／矩形轮廓，提示高亮宽度 | 透明高亮带，使用独立标注混合方式 |
| 橡皮 | 与作用范围相符的圆形轮廓，附小橡皮提示 | 擦除轨迹／待删除对象反馈；只作用于标注层 |
| 套索（后续） | 套索图标 + 中心点 | 虚线选区，不产生手写 |
| 阅读／拖动 | 手形图标 | 拖动页面 |
| 文字（后续） | 文本定位图标 | 点击后进入独立文本输入 |

可设置轮廓／图标／十字、悬停显示开关、落笔时是否保留中心点。首版先提供实用默认值，不把整个 PS 光标设置面板搬入应用。

光标热点是实际落笔点，笔尖图标的尖端而非整张图标中心必须对准事件坐标。白色扫描页和深色页上使用黑白双描边，不能只靠当前笔色区分。名义粗细不由悬停 pressure=0 推导为零；实际笔迹仍按接触压力绘制。未取得有效压力前展示名义笔宽。

### 实现与状态

优先以画布最上方的 CursorOverlay 提供动态轮廓；同时验证 View.onResolvePointerIcon / PointerIcon 对系统笔指针的定制能力，避免系统指针与应用轮廓形成两个互相偏移的光标。若目标固件不能抑制系统指针，切换为系统自定义指针优先的方案，限制动态预览范围并明确取舍；不宣称已经解决。

Android 官方的自定义编辑器文档说明可重写 onResolvePointerIcon 获取 stylus 悬停图标，但它不保证每台 Wacom 固件上的表现完全一致。本项目已有真实 HOVER_ENTER / HOVER_MOVE / HOVER_EXIT，说明位置输入有依据；是否能完全替换系统图标须真机原型确认。

- 工具被选中且笔进入可编辑页面区域时显示；切换工具在下一显示帧更新。
- 笔抬离可检测范围、移出页面、打开菜单、失焦、取消或进入导航区域时隐藏／切换相应光标，不留下旧位置。
- HOVER_EXIT 可能意味着开始接触，也可能离开范围；落笔状态依据后续 DOWN 处理。HOVER_EXIT 不是物理侧键松开。
- 画布缩放或滚动时，即使笔没有新移动，也用最新屏幕位置与页面矩阵重新确定落点。
- 可滚动容器、菜单和控件边界重新命中；避免用 View 的旧局部坐标画到新布局。
- 光标刷新与输入热路径不等待 PDF 渲染，不写入数据库、不导出、不进入撤销记录。
- 原始 RZ 在用户日志中恒定，不能依赖它驱动笔杆旋转光标；首版只根据工具设置绘制形状。

## 8. 笔键与手势协作

沿用用户编号：第一键 0x20，第二键 0x40，第三键 0x04，无按键 0。通过相关 motion 的 buttonState 变化识别，独立 BUTTON_PRESS/RELEASE 走同一路径去重。系统 source 可能包含组合能力位，设备 ID 不写死。

按钮识别与功能绑定分离；本计划不擅自指定三个按键的用途。用户已明确工具绑定要支持下列两种可配置模式：

| 模式 | 按下时 | 保持按住时 | 松开时 |
| --- | --- | --- | --- |
| 按住临时启用（HOLD） | 暂时启用目标工具，保留原工具状态 | 持续使用目标工具 | 恢复之前的工具及其设置 |
| 按下直接切换（SELECT） | 将目标工具设为当前选中工具 | 保持目标工具，不重复触发 | 不恢复，继续使用目标工具 |

配置以每个快捷绑定为单位，包含按钮位、目标工具／预设和触发模式；三个侧键可独立设置。比如“某键 → 橡皮 → 按住临时启用”和“某键 → 荧光笔 → 按下直接切换”是配置示例，不代表已为物理按键指定默认用途。普通工具栏点击仍是直接选中工具。

直接切换只在按钮从未按下变成按下的边沿触发；长按期间连续到来的 MOVE/HOVER_MOVE 不重复执行。再次按同一个 SELECT 绑定仍选中该目标工具，不自动变成两工具来回切换；若以后需要 toggle，应作为第三种明确模式提出。

HOLD 恢复的是完整工具上下文，例如原来的笔刷、颜色、粗细等；进入临时工具及恢复时光标同步变化。失焦／取消时结束临时覆盖，不能卡在临时橡皮；SELECT 的已选工具不因松键而回退。悬停离开只隐藏光标，不把 HOVER_EXIT 当成物理松键。

建议的冲突规则（尚属规划默认值）：在临时工具期间通过工具栏或 SELECT 明确选中另一个工具时，结束旧临时覆盖，以新选择为准；随后旧侧键松开不能把新选择回滚。多键同时按下的硬件组合尚未验证；若支持多个 HOLD，使用明确的覆盖优先级并测试乱序松开，避免恢复到已释放的临时工具。

笔触中途按下／松开产生工具变化时先定义清晰的笔迹提交边界，不能把同一对象的一半变成另一工具，也不能因松键丢弃已经完成的擦除或标注操作。工具的临时启用不代表临时编辑结果会在松键时撤销。

笔、手指、鼠标按设备／source／pointer 和交互流分开追踪。手指的 CANCEL 不能误删已提交笔迹，也不能无条件取消另一个设备正在画的笔。现有诊断图层仅作为临时显示，不直接沿用其全局取消逻辑。

## 9. 保存、备份与导出

| 用户目的 | 建议形式 | 是否保留可编辑性 |
| --- | --- | --- |
| 日常继续标注 | 应用内底稿 + 独立标注数据库 | 完整保留 |
| 同一底稿的轻量转移 | 带资产哈希、格式版本的标注包；导入时校验底稿 | 保留，但接收设备必须有同一底稿 |
| 完整离线备份 | 原 PDF + 标注 + 清单的文档包，流式打包 | 保留；大文件按原大小占空间 |
| 给其他阅读器查看 | 新建带标注 PDF，优先支持选页／页范围导出 | 取决于导出能力；应用标注包始终保留 |

完整备份是手动／受控任务，不在每次抬笔时重打包整书。多文档共享底稿使用引用计数或等效机制，删除一个笔记条目不能误删另一条目的底稿。导入标注包时哈希不一致必须拒绝自动套用，防止同名但页序不同的文件错位。

通用 PDF 导出需要额外原型：尽量保留原页面图像压缩、文本、链接与页面旋转，在新文件上叠加矢量笔迹；不要默认整本扫描书重新栅格化，造成体积膨胀和文字层丢失。系统 API 是否足够、是否引入其他引擎由 Android 15 实测和输出兼容性决定。首个可用版本不以通用 PDF 导出为前置条件，但必须能可靠恢复和备份独立标注。

若导入 PDF 本身包含可见批注，作为底稿的一部分显示；用户标注层的隐藏／擦除不修改它们。加密文件原型先验证密码读取；密码错误、不支持的安全方案或损坏文件给出明确提示，不能绕过限制。密码默认只在当前会话内保留。

### B2 分拆及 B2a 已实施计划：原始 manifest 字节保真锚点升级

B1b 本地提交 c5d0d4ac。B2 不以进程 Page.uid 或 GlueIds 的位置序号冒充稳定身份，分为三步：B2a 升级基础，B2b 模型／编解码／快照／复制与显式存储接入，B2c 碎片等确定后继和删除／移动／撤销语义。C1 对象引用必须等依赖完成，不能提前按位置匹配。

复用 JsonPull 识别精确结构，不经 JSON DOM／模型重新输出。给该内部 parser 增加消费字符位置（UTF-16 code units）与严格末尾检查，不改变现有默认读写行为。第一次只读取并记录新增字段的插入位置／UUID；第二次严格 UTF-8 解码、原字符片段流式复制和插入，再 UTF-8 编码。合法 UTF-8 原字节往返不变，数字字面量、空格、未知字段、笔压／时间字符串和原 PDF 不重新序列化。需核实 JsonPull 跳过值的严格性，对此升级路径增加必要的词法／深度／容量校验，拒绝尾随垃圾／畸形输入／取消。原 JSON 大内容不整份驻留内存；只保留对象ID和插入点。
